# Q3 — Calculator worker + controller (fork + exec, parallel requests)

A company has a small standalone calculation utility (calc_worker) that takes two numbers and an operation as command-line arguments,
and prints the result. A separate controller program (controller.c) needs to invoke this utility as a child process whenever a
calculation request comes in — instead of embedding the calculation logic directly — so the worker can be updated/replaced
independently without touching the controller.

Accepts three command-line arguments: num1, operator (+, -, *, /), num2. Prints the result.

Additionally after this the program should be able do atleast two operations parallely.

## Compile & run

**q3_calc_worker.c**

*the controller execs "./calc_worker", so use exactly this output name*

```text
  gcc -Wall -o calc_worker q3_calc_worker.c
```

**q3_controller.c**

*in the same folder as calc_worker*

```text
  gcc -Wall -o calc_worker q3_calc_worker.c
  gcc -Wall -o controller q3_controller.c
  ./controller
```

## Expected output

**q3_calc_worker.c**

*alone*

```text
  ./calc_worker 8 - 3      ->  calc_worker (PID 13838): 8 - 3 = 5.00
  ./calc_worker 8 x 3      ->  calc_worker (PID 13841): 8 x 3 = 24.00
  ./calc_worker 8 '*' 3    ->  (quote *, or the shell replaces it with file names)
  ./calc_worker 7 / 0      ->  calc_worker: 7 / 0 -> cannot divide by zero   (exit code 2)
```

**q3_controller.c**

*Ubuntu; worker lines can come in any order = they run in parallel*

```text
  controller: request 1 (60 + 40) -> worker PID 13879
  controller: request 2 (100 * 16) -> worker PID 13881
  controller: request 3 (7 / 0) -> worker PID 13884
  calc_worker (PID 13879): 60 + 40 = 100.00
  calc_worker: 7 / 0 -> cannot divide by zero
  calc_worker (PID 13881): 100 * 16 = 1600.00
  controller: worker 13879 finished, exit code 0
  controller: worker 13881 finished, exit code 0
  controller: worker 13884 finished, exit code 2
  All calculations completed.
```

## Answers

**q3_calc_worker.c**

Exit codes tell the controller what happened: 0 ok, 1 usage, 2 divide by zero, 3 bad operator.

**q3_controller.c**

**Why it is parallel:** ALL children are forked before the first waitpid(). If you wrote
fork -> waitpid -> fork -> waitpid, the second calculation would start only after the
first finished (sequential).

**Why a separate program:** the controller only knows the worker's name and arguments, so
calc_worker can be recompiled/replaced without touching the controller.

**Why fflush(stdout) before fork():** if exec fails, the child's exit() would flush a copy
of the parent's unprinted buffer and lines would appear twice.
