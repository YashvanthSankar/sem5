# Q2 — Backup utility: child runs cp with exec, parent keeps logging

A system administrator wants a utility that copies (backs up) a file to a backup location. Instead of writing the copy logic manually,
the program should use the existing Linux command internally — but run it as a child process, so the parent process can continue
doing other work (like logging) while the copy happens.

Sample code:
```c
#include <stdio.h>

int main(int argc, char *argv[]) {
    printf("Number of arguments: %d\n", argc);
    for (int i = 0; i < argc; i++) {
        printf("argv[%d] = %s\n", i, argv[i]);
    }
    return 0;
}
```

## Compile & run

```text
  gcc -Wall -o q2 q2.c
  ./q2 src.txt dst.txt
  ./q2 nofile.txt dst2.txt
```

## Expected output

*Ubuntu; order of the first lines can vary, it's two processes*

```text
  Child (PID 13811): running cp src.txt dst.txt
  Parent (PID 13808): child 13811 is copying, I am logging...
  Parent: log -> backup of src.txt requested
  Parent: backup completed (src.txt -> dst.txt)

  Child (PID 13820): running cp nofile.txt dst2.txt
  cp: cannot stat 'nofile.txt': No such file or directory
  Parent (PID 13817): child 13820 is copying, I am logging...
  Parent: log -> backup of nofile.txt requested
  Parent: backup FAILED (cp exit code 1)
```

## Answers

**Points to say in the viva:**
- exec replaces the child's program with cp; it returns ONLY on failure, so the line
  after execlp() is the error path.
- execl needs the full path ("/bin/cp"); execlp searches $PATH ("cp").
- argv list: argv[0] is the program name ("cp"), and the list ends with (char *)NULL.
- The parent runs concurrently with the copy; waitpid() at the end avoids a zombie
  and gives the child's exit code (WIFEXITED / WEXITSTATUS).
- The "sample code" in the question (printing argc/argv) is only there to show how
  command-line arguments arrive: ./q2 a b -> argc = 3, argv[1]="a", argv[2]="b".
