# Q4 — Orphan: child waits for parent to die, prints old and new parent PID

Write a program where a child is created from a parent and a child waits
for a parent to end. As soon as the parent ends child prints the dead parents id and also new parants id without sleep.

## Compile & run

```text
  gcc -Wall -o q4 q4.c
  ./q4
```

## Expected output

*PIDs vary*

```text
  Parent: PID 13847, exiting now
  Child (PID 13850): dead parent's PID = 13847
  Child (PID 13850): new parent's PID  = 1
  (the child's lines may appear after the shell prompt, because the shell only waits
   for the parent)
```

## Answers

The new parent is "init" (PID 1) in a plain Linux/Docker shell. On Ubuntu desktop it is
often NOT 1 but the PID of `systemd --user` (a "subreaper", e.g. 1534). Check with:
ps -o pid,comm -p <new ppid>

**Theory:**
- Orphan: a process whose parent exited first. The kernel re-parents it to init (or the
  nearest subreaper), which will wait() for it, so an orphan never stays a zombie.
- Save the parent’s PID with `getpid()` before `fork()`. The child inherits that value and polls `getppid()` until it differs. The child may already have been re-parented by the time it first runs.
- Orphan vs zombie: orphan = parent dead, child alive; zombie = child dead, parent alive
  but has not called wait().
