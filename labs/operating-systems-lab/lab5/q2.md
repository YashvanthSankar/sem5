# Q2 — Mutex

[Open the exam solution](q2.c)

**Problem: Thread-Safe Bank Account**

Write a C program using Pthreads and a mutex to simulate transactions on a shared bank account.

Initial Account Balance = ₹10,000

- Create three threads.
- Thread 1: Deposit ₹2,000, 5 times.
- Thread 2: Withdraw ₹1,000, 5 times.
- Thread 3: Deposit ₹500, 5 times.
- All three threads access the same shared balance variable.
- Each transaction must be protected using a mutex so that only one thread modifies the balance at a time.

Requirements:

- Create three threads using pthread_create().
- Use a shared balance variable.
- Protect the balance update using pthread_mutex_lock() and pthread_mutex_unlock().
  ```c
  pthread_mutex_lock(&mutex);
  /* update balance */
  pthread_mutex_unlock(&mutex);
  ```
- Use pthread_join() for all three threads.
- Display the final account balance.

Expected final balance:

```
Initial = 10000

Thread 1: +2000 × 5 = +10000
Thread 2: -1000 × 5 =  -5000
Thread 3:  +500 × 5 =  +2500

Final = ₹17,500
```

Concepts tested: Race condition, critical section, mutex, and mutual exclusion.

## Exam solution

Use one worker. Give each thread a stable pointer to its signed amount (2000, -1000, or 500). In each of five iterations, lock, add the amount to the shared balance, and unlock. Join all three before printing.

`gcc -Wall -Wextra q2.c -o q2 -pthread && ./q2`

Expected final balance: **17500**. Two unprotected updates can read the same old balance and overwrite each other. Protect each entire read–modify–write.
