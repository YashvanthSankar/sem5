# Q4 — Concurrent Banking Engine (Transfers plus Live Audits)

[Open the exam solution](q4.c)

**Scenario**

You're building the core of a payment system. It holds N accounts (say 1,000) and serves many threads at once:

- Transfer threads move money between two random accounts.
- Audit thread(s) periodically compute the total money in the system.
- Account-closure thread occasionally freezes an account so no more transfers touch it.

**Rules**

1. Use only pthread_create, pthread_join, and pthread_mutex_*. No condition variables, semaphores, rwlocks, or atomics.
2. Money is conserved. The total after any number of transfers must equal the initial total.
3. A transfer must fail (return an error) if the source balance is insufficient. Balances never go negative.
4. No deadlocks, even when thread A does transfer(5→9) while thread B does transfer(9→5).
5. An audit must see a consistent snapshot. It must never observe money "in flight" (debited from one account but not yet credited to the other).
6. A frozen account rejects all transfers in or out.
7. No global lock for transfers. Two transfers on disjoint account pairs must be able to run in parallel.

(The rules are numbered here for reference; the sheet lists them without numbers.)

## Exam solution

- Transfer: reject invalid accounts, equal accounts, and nonpositive amounts. Acquire both account locks in ascending order. Under both locks check both frozen flags and the source balance, then debit and credit. Release both locks and return 0 on success or -1 on failure.
- Audit: lock all accounts ascending, sum the balances, then release the locks. The auditor cannot see a transfer halfway through.
- Closure: acquire one account lock, set its frozen flag, release it. Transfers check the flag on both accounts under those same locks.
- Main: initialize accounts, start two random-transfer workers, an auditor and a closure worker before joining any of them. Disjoint transfers can run concurrently.

`gcc -Wall -Wextra q4.c -o q4 -pthread && ./q4`

Every audit and the final total should be **1000000**. Ascending lock order breaks circular wait. Rejecting self-transfers avoids acquiring the same nonrecursive mutex twice.
