# Q1 — Pthread without Synchronization

[Open the exam solution](q1.c)

**Problem: Parallel Calculation of Student Statistics**

Write a C program using POSIX threads (Pthreads) to calculate statistics for an array of student marks. The main thread should create two worker threads.

- Thread 1: Calculate the sum of marks in the first half of the array.
- Thread 2: Calculate the sum of marks in the second half of the array.
- The two threads should store their results in shared variables.
- After both threads complete, the main thread should calculate and display the total sum and average.

Requirements:

- Use pthread_create() to create the two threads.
- Use pthread_join() to wait for both threads.
- Pass the array and required information to the threads using the thread argument.
- Do not use mutexes or semaphores.
- Display the sum calculated by each thread, total sum, and average.

Concepts tested: Thread creation, function arguments, shared memory, and pthread_join().

## Compile, run and expected output

```text
Compile:  gcc -Wall -Wextra q1.c -o q1 -pthread
Run:      ./q1

Expected output (checked on Linux, same every run):
  thread 1 sum = 357
  thread 2 sum = 293
  total sum = 650
  average = 65.00

  (first half 97+85+98+54+23 = 357, second half 45+78+27+67+76 = 293, 650/10 = 65.00)
```

## Answers (viva)

```text
1. Why is no mutex needed?
   The threads only READ the array and each WRITES a different variable (sum1 / sum2).
   A data race requires conflicting accesses to the same location without synchronization.
   Each result has one writer, and main reads it after joining that worker.

2. What does pthread_join() do here?
   It blocks main until that thread has finished. After it returns, the thread's write to
   sum1/sum2 is complete and visible to main. Without the joins, main could print 0 or a
   half-finished sum, or exit and kill the threads.

3. How are arguments passed?
   Pass marks to the first worker and marks + HALF to the second. Each pointer starts
   at the first element of its five-mark half. Both workers call sum_half(), then store
   their results in separate variables. The array stays alive until both joins finish.

4. Shared memory between threads:
   Threads of one process share globals, the heap and (through pointers) each other's stacks.
   That is why the thread can write sum1 and main sees it. Processes after fork() do NOT share
   memory like this.

5. Returning a value instead (alternative): the thread can return (void*) a malloc'd int,
   and main reads it with pthread_join(t1, &ret).
```
