# Q1 — Print Spooler with Priority Jobs (Producer–Consumer, bounded buffer)

[Open the exam solution](q1.c)

A print server has a spooler queue that can hold at most 8 print jobs. Three student terminals act as
producers, each submitting jobs of two kinds, normal and priority, while two printers act as consumers.
A printer must always pick a priority job if one is waiting in the queue, and only otherwise a normal job,
but it must never remove a job from an empty queue. Producers must never add a job to a full queue, and
the queue contents must never be corrupted by simultaneous access. Write a multithreaded program in C
using POSIX threads and semaphores that simulates this system. Each producer submits 10 jobs with random
delays, and each printer prints jobs until the total of 30 jobs have been served, after which all threads
must terminate cleanly. Print a log showing which terminal produced which job, which printer consumed it,
and the queue occupancy after every operation.

What the question requires, as a checklist:

- Queue capacity 8; 3 producers (terminals); 2 consumers (printers).
- Jobs are *normal* or *priority*; a printer takes a priority job whenever one is queued.
- Never remove from an empty queue; never add to a full queue; no corruption from simultaneous access.
- POSIX threads + semaphores.
- 10 jobs per producer with random delays; 30 jobs in total; then every thread terminates cleanly.
- Log: terminal → job, printer ← job, queue occupancy after every operation.

## Exam solution

- Initialize `empty = 8`, `full = 0`. One mutex protects the array and occupancy.
- Producer: wait for `empty`, lock, append, log, unlock, post `full`.
- Printer: wait for `full`, lock, exit if the queue is empty after waking. Otherwise remove the first priority job or index zero, shift left, log, unlock, post `empty`, then simulate printing.
- Main: join all producers, post `full` once per printer, then join both printers. Each post covers one exit. Queued jobs are still selected in priority order.
- Never wait on a semaphore while holding the queue mutex. The thread that could free a slot or insert a job needs that mutex.

Only the producers use random delays. Each uses its terminal ID as its seed. Both printers use a fixed print delay.

On Linux, run `gcc -Wall -Wextra q1.c -o q1 -pthread && ./q1`. Expect 30 submissions and 30 removals, occupancy 0–8, and both printers finishing with an empty queue.
