# Q1 — Trace the Existing sleep() System Call (10 marks)

Lab 7, xv6-public (x86). Copied word for word from the lab sheet.

Consider the following user program:

```c
#include "types.h"
#include "user.h"

int main(void)
{
    int pid = getpid();
    printf(1, "Before sleep: PID = %d\n", pid);
    sleep(100);
    printf(1, "After sleep: PID = %d\n", pid);
    exit();
}
```

Tasks
1. Trace sleep(100) from user mode to kernel mode and back.
2. Identify the relevant source files and functions, starting with usys.S.
3. Explain system call number identification and how the argument 100 is passed to the kernel.
4. Explain the roles of sys_sleep(), the ticks counter, internal sleep(), wakeup(), and timer interrupts.
5. Describe the process-state transitions RUNNING → SLEEPING → RUNNABLE and subsequent resumption.
6. Draw the complete system call flow, including return to user mode.

Handout self-check questions also answered below:
1. Why is a user.h prototype not enough to implement a system call?
2. What does SYSCALL(getppid) generate conceptually?
3. Why must every system call have a unique number?
4. What does syscall.c read from the saved EAX register?
6. What is the difference between user sleep(100) and kernel sleep(&ticks, &tickslock)?

---

## Short exam answer

`sleep(100)` calls the stub in `usys.S`. The stub loads EAX with 13 and executes `int $64`.
`vector64 → alltraps → trap() → syscall()` saves the registers and dispatches to `sys_sleep()`.
`argint(0, &n)` reads 100 at the saved user ESP + 4, past the return address.

`sys_sleep()` saves `ticks0` under `tickslock` and loops while `ticks - ticks0 < 100`.
Kernel `sleep(&ticks, &tickslock)` sets RUNNING → SLEEPING. CPU 0's timer increments ticks and
calls `wakeup(&ticks)`, making the waiting process RUNNABLE. When scheduled again it is RUNNING
and checks the elapsed ticks. This can repeat across many ticks.

After 100 ticks, `sys_sleep()` returns 0. `syscall()` writes 0 into saved EAX.
`popal` in `trapret` restores the general-purpose registers, including EAX. `iret` resumes the user stub. The stub's `ret` returns to main.

## Answers

### Task 2 — files and functions
| File | What it has |
|---|---|
| `user.h` | `int sleep(int);`: the prototype, so `main()` compiles |
| `usys.S` | `SYSCALL(sleep)`: the user stub `movl $SYS_sleep,%eax; int $T_SYSCALL; ret` |
| `syscall.h` | `#define SYS_sleep 13`: the syscall number |
| `vectors.S` | `vector64`: the IDT entry for `int $64` (`T_SYSCALL` = 64) |
| `trapasm.S` | `alltraps` builds the trapframe; `trapret` restores it and does `iret` |
| `trap.c` | `trap()`: `T_SYSCALL` → `syscall()`; timer IRQ → `ticks++`, `wakeup(&ticks)` |
| `syscall.c` | `syscall()`, `argint()`, `fetchint()`: dispatch + reading arguments |
| `sysproc.c` | `sys_sleep()`: the handler |
| `proc.c` | `sleep()`, `wakeup()`, `wakeup1()`, `sched()`, `scheduler()` |

### Tasks 1, 3 — user mode → kernel mode, syscall number, argument
1. `main()` calls `sleep(100)`. The compiler pushes **100 on the user stack**, then `call sleep` pushes the return address.
2. The usys.S stub puts the number in EAX: `movl $SYS_sleep, %eax` (EAX = 13). **This is how the kernel knows which call it is.**
   Then `int $64`.
3. The CPU looks up IDT entry 64 (`vector64`). Its gate has DPL = user, so user code may use it. The CPU switches to the
   process's **kernel stack** (`esp0` from the TSS) and pushes `ss, esp, eflags, cs, eip`.
4. `alltraps` (trapasm.S) pushes the other registers. That block is the **trapframe**. It then calls `trap(tf)`.
5. `trap()` sees `tf->trapno == T_SYSCALL`, sets `myproc()->tf = tf` and calls `syscall()`.
6. `syscall()`: `num = curproc->tf->eax` (13), checks `num > 0 && num < NELEM(syscalls)`, then
   `curproc->tf->eax = syscalls[num]();`, which calls `sys_sleep()`.

**How 100 gets to the kernel:** it is on the user stack, not in a register.
`argint(0, &n)` → `fetchint(myproc()->tf->esp + 4 + 4*0, &n)`. `tf->esp` is the saved user stack pointer, `+4` skips
the return address, and index 0 means the first argument (not the syscall number). `fetchint()` checks that the address
is inside the process (`< p->sz`) before it reads.

### Task 4 — sys_sleep(), ticks, internal sleep(), wakeup(), timer
```c
int
sys_sleep(void)
{
  int n;
  uint ticks0;

  if(argint(0, &n) < 0)          // n = 100
    return -1;
  acquire(&tickslock);           // ticks is shared: protect it
  ticks0 = ticks;                // remember the start tick
  while(ticks - ticks0 < n){     // fewer than 100 ticks passed?
    if(myproc()->killed){        // killed while waiting -> -1
      release(&tickslock);
      return -1;
    }
    sleep(&ticks, &tickslock);   // block on channel &ticks
  }
  release(&tickslock);
  return 0;
}
```
- **ticks** is a global counter in trap.c. It goes up by 1 on every timer interrupt (only on CPU 0). **tickslock** protects it.
- **Timer interrupt:** `trap()` case `T_IRQ0+IRQ_TIMER` runs `acquire(&tickslock); ticks++; wakeup(&ticks); release(&tickslock);`.
- **Kernel `sleep(chan, lk)`** (proc.c): `acquire(&ptable.lock); release(lk);` (swapping the two locks means no wakeup is lost),
  then `p->chan = chan; p->state = SLEEPING; sched();`. When the process resumes: `p->chan = 0; release(&ptable.lock); acquire(lk);`.
- **`wakeup(chan)`** → `wakeup1()`: every process with `state == SLEEPING && chan == chan` becomes RUNNABLE.
- **Self-check 6:** user `sleep(100)` is a *system call* asking for a 100-tick delay. Kernel `sleep(&ticks, &tickslock)`
  is an *internal function* that blocks the process on a channel.
- **Important:** `wakeup(&ticks)` happens on **every** tick. The process can wake and run on many of those ticks, depending on scheduling. Each time it re-checks
  `ticks - ticks0 < n` and goes back to sleep until 100 ticks have passed.

### Task 5 — state transitions
```
RUNNING   executing main(), then sys_sleep() in the kernel
   | sleep(&ticks,&tickslock): state = SLEEPING, sched()
   v
SLEEPING  off the CPU; the scheduler runs other processes
   | timer tick: ticks++, wakeup(&ticks)
   v
RUNNABLE  ready, waiting for a CPU
   | scheduler(): c->proc = p; p->state = RUNNING; swtch()
   v
RUNNING   continues inside sleep(), back in sys_sleep()'s while loop
   +--> fewer than 100 ticks: sleep again (SLEEPING)
   +--> 100 ticks passed: leave the loop, return 0
```

### Return to user mode
`syscall()` stores the handler’s return value, 0, in the saved EAX slot. When `trap()` returns,
`popal` in `trapret` restores EAX and the other general-purpose registers. Then `iret` restores
the user instruction pointer, stack pointer, flags, CS and SS. The stub executes `ret`,
so `main()` receives 0 and prints "After sleep".

### Task 6 — complete flow
```
main(): sleep(100)                       [user mode]  100 pushed on user stack
  -> usys.S: EAX = 13 (SYS_sleep), int $64
================ user -> kernel ================
  -> vectors.S vector64 -> trapasm.S alltraps (build trapframe)
  -> trap.c trap(): T_SYSCALL -> syscall()
  -> syscall.c: num = tf->eax = 13 -> sys_sleep()
  -> sysproc.c sys_sleep(): argint(0,&n) reads tf->esp+4 -> n = 100
  -> acquire(tickslock), ticks0 = ticks
  -> loop: proc.c sleep(&ticks): RUNNING -> SLEEPING -> sched() -> scheduler
       <- timer IRQ: trap.c ticks++, wakeup(&ticks): SLEEPING -> RUNNABLE
       <- scheduler(): RUNNABLE -> RUNNING, re-check ticks - ticks0 < 100
  -> 100 ticks passed: release(tickslock), return 0
  -> syscall(): tf->eax = 0 -> trap() returns -> trapret: popal -> iret
================ kernel -> user ================
  -> stub ret -> main(): printf("After sleep ...") -> exit()
```

### Handout self-check answers
1. A user.h prototype only lets the C code compile. Without the usys.S stub there is no code to link (undefined reference).
   Without the syscall.c table entry and the handler, the kernel prints "unknown sys call".
2. `SYSCALL(getppid)` generates: `.globl getppid; getppid: movl $SYS_getppid, %eax; int $T_SYSCALL; ret`.
3. The number is the only thing the kernel sees when it picks the handler (it indexes `syscalls[]`). Two calls with one
   number would run the same handler.
4. `syscall()` reads the system call **number** from `tf->eax`. Later it writes the **return value** back into `tf->eax`.
