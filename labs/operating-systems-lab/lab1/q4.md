# Q4 — make a zombie, show it with ps (Z), then reap it with wait()

Create a child process that prints its PID and exits immediately. In the parent, sleep for 10 seconds without calling wait(),
then run ps to show the child is now a zombie (Z state). After the sleep, call wait() and show the zombie disappears.

## Compile & run

*Linux*

```text
  gcc -Wall -o q4 q4.c
  ./q4
```

## Expected output

*tested on Ubuntu 24.04; PIDs vary*

```text
  Child: PID 12983, exiting now
  Parent: PID 12639, sleeping 10 s without wait()

  Before wait():
      PID    PPID STAT COMMAND
    12983   12639 Z    q4            <- Z = zombie (ps aux shows "[q4] <defunct>")

  After wait():
      PID    PPID STAT COMMAND           <- header only: the zombie is gone

You can also watch from a second terminal during the 10 s:
  ps -el | grep Z        or        ps aux | grep defunct
```

## Answers

**Theory:**
- Zombie: a process that has exited but whose parent has not yet called wait().
  Its memory is freed, but its PCB entry (PID + exit status) stays so the parent
can collect the status.
- wait() reads that exit status and removes the entry -> zombie disappears.
- If the parent never waits and exits, init/systemd adopts the zombie and reaps it.
