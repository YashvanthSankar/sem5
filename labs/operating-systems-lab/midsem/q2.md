# Q2 — Scenario 3: The Spice Traders of Malabar

Time: 90 minutes | Language: C (Linux)

Allowed: fork, wait, exit, getpid, getppid, sleep, shmget, shmat, shmdt, rand, srand. Shell commands ipcs -m and ipcrm -m are also allowed.

Not allowed: threads, semaphores, locks, pipes, signals, shmctl. No synchronization is needed, since every process writes only to its own slot
and every reader reads only after wait() returns.

```c
struct Result { int count[3]; int porter_pid; int porter_ppid; };
struct Warehouse {
    struct Result porter[4][2];   // written only by that porter
    int dock_total[4][3];         // written only by that dock
    int dock_pid[4];
    struct Result *best;          // used in Part 3
    int best_idx;                 // used in Part 3
};
```

**Part 1: The Harbourmaster's Register Opens**
On the Malabar coast, ships arrive daily loaded with three goods: A (pepper), B (cardamom) and C (cinnamon). The Harbourmaster (the parent
process) opens a huge shared register (shared memory) on the pier, because a porter's private tally-stick (private memory) can never be seen
by anyone else. Write the code in which the Harbourmaster creates this register with shmget using sizeof(struct Warehouse) and attaches it
with shmat before any fork(), checking errors with perror. **(3)**

The harbour has four docks, each managed by a child of the Harbourmaster. Use a fork() loop to send a dock supervisor to each dock, taking
care that no supervisor accidentally sends out more supervisors of his own. Each dock writes its PID into dock_pid[i]. The Harbourmaster then
calls wait() four times so that no zombie processes remain, and detaches with shmdt. **(3)**

**Part 2: The Porters Begin Unloading**
Each dock is too busy to unload alone, so every dock calls two porters using fork(), giving 1 + 4 + 8 = 13 people working on the pier. Each
porter writes his getpid() and getppid() into the register and unloads 50 sacks into his own porter[i][j].count, using rand() seeded with his
PID (values 0 to 2 for pepper, cardamom, cinnamon). He then leaves with exit. **(3)**

The dock waits for both porters, adds their counts into dock_total[i], and exits. Finally, the Harbourmaster reads the register and announces
the dock-wise totals, the grand total (which must be 400) and which spice was unloaded the most, or "Tie". **(3)**

**Part 3: Trouble at the Harbour**

*Trouble 1: The Private Tally-Stick (2).* A careless porter keeps a global int local_count = 0; and adds one per sack. Show that the
Harbourmaster prints 0 for it while the register shows real values, and explain in two lines why a global variable is not shared even though
the porter was created by fork().

*Trouble 2: The Address That Moved (2).* The Harbourmaster stores best = &porter[i][j] in the register to mark the fastest porter, then walks
onto the pier through a second gangway (a second shmat) and reads best->count[]. Show that the pointer gives a wrong result there, and fix it
by storing best_idx and reading porter[best_idx / 2][best_idx % 2].

*Trouble 3: The Late Dock (2).* Dock 4's supervisor arrives late and builds his own private register with shmget(IPC_PRIVATE, ...) after being
forked, so the Harbourmaster sees zeros for Dock 4. Fix this, and explain why the register must be created and attached before fork(). Then use
sleep(20) in the porters and run ipcs -m in another terminal to report nattch, which should be 13. Explain what remains listed after everyone
detaches, and how ipcrm -m clears it.

*Trouble 4: The Orphan Porters (2).* Make one dock leave without waiting for its porters. Show that a porter's recorded ppid differs from his
current getppid(), and explain why the original version, where the dock waits, has no orphans.
