# Q1 — one pipe, parent writes "Hello, Child!", child reads and prints it

Write a C program that creates a pipe and then uses fork() to create a child process;
the parent process should write the string "Hello, Child!" into the pipe,
while the child process reads that message from the pipe and
prints it to the screen in the format "Child received: Hello, Child!" — remembering that since only one-way communication
is needed (parent to child), each process should close the pipe end it doesn't use.

## Compile & run

```text
  gcc -Wall -o q1 q1.c
  ./q1
```

## Expected output

```text
  Child received: Hello, Child!
```

## Answers

**Key points:**
- pipe(fd) BEFORE fork(), so both processes get the same two ends.
- fd[0] = read end, fd[1] = write end. Each process closes the end it does not use:
  parent closes fd[0], child closes fd[1].
- Closing the unused write end in the child matters: read() returns 0 (EOF) only when
  EVERY write end is closed. If the child kept fd[1] open, a second read() would block forever.
- write(..., strlen(msg)+1) sends the '\0'; buffer[n] = '\0' terminates whatever arrived.
