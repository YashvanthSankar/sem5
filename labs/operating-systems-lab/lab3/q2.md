# Q2 — calculator worker with TWO pipes (two-way communication)

Write a C program that simulates a simple calculator worker process using two pipes
for two-way communication, where the parent process sends two integers and an operator (+, -, *, or /)
to the child (for example, "12 4 +"), the child reads these values,
performs the corresponding arithmetic operation, and sends the result back to the parent,
which then prints the final output in the format "Result of 12 + 4 = 16"; the program should
use one pipe for parent-to-child communication and a separate pipe for child-to-parent communication,
handle division by zero gracefully by having the child send back an error code instead of crashing,
ensure all unused pipe ends are properly closed in both processes, and use wait() in the parent to avoid leaving a zombie child process.

## Compile & run

```text
  gcc -Wall -o q2 q2.c
  ./q2            then type:  12 4 +
```

## Expected output

*one run per input*

```text
  12 4 +  ->  Result of 12 + 4 = 16
  12 4 -  ->  Result of 12 - 4 = 8
  12 4 *  ->  Result of 12 * 4 = 48
  12 4 /  ->  Result of 12 / 4 = 3
  12 0 /  ->  Error (code -1): division by zero
  12 4 %  ->  Error (code -2): invalid operator '%'
  abc     ->  Bad input
  (each line is preceded by the prompt "Enter input (a b op), e.g. 12 4 + : ")
```

## Answers

**Key points for the viva:**
- Why two pipes: a pipe is one-way. With ONE pipe used both ways, the parent could
  read back its own data before the child does.
- Unused ends: parent closes p2c[0] and c2p[1]; child closes p2c[1] and c2p[0].
  Then each read() sees EOF if the other side dies, instead of blocking forever.
- Division by zero: the child never divides; it sends code -1 and the parent prints the
  error. The child does not crash (a/0 on ints would kill it with SIGFPE).
- wait(NULL) at the end reaps the child, so no zombie.
- No deadlock: the parent writes everything, then reads; the child reads everything,
  then writes. Neither waits for something the other has not sent yet.
