Develop a client-server role-based file access system using Python socket programming with the following properties:
Develop both server.py and client.py programs. Use a simple Python GUI (Tkinter) for interaction.
The server should maintain a collection of preloaded files belonging to different categories such as Academic, Administrative.
Define three hierarchical user roles, where each higher role is a superset of the permissions available to the lower role. For example:
Role 1 – Student: View/download files under the Academic category.
Role 2 – Faculty: All Student permissions + upload/update file in Academic category and View/download files under the Administrative  category.
Role 3 – Administrator: All Faculty permissions + upload/update Administrative files.
The client should initially provide a username to connect to the server. The server should validate the credentials/role before granting access. A set of various types of users and their roles will be assigned in the server. The server must maintain the actual access-control policy and should not rely on the client to enforce permissions.After authentication, the client should receive a list of operations available to that role and the relevant files.Provide operations such as LIST, READ/DOWNLOAD, UPLOAD, and UPDATE, depending on the user's role.The server should maintain a file-access log containing the username, role, requested file, operation, timestamp, and whether the request was allowed or denied,  file modifications, and client disconnection.If a user requests an operation or file outside their permission level, the server should deny the request and return an appropriate message to the client.The client GUI should display the available files, operations, server responses, and access status.The client should provide an EXIT option to terminate the session safely.
