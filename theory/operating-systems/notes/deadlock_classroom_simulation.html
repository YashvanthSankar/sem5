Quick comparison

ApproachWhat the OS doesWhen?
PreventionDesign rules so at least one necessary deadlock condition cannot hold; e.g., enforce a global resource order.Before deadlock
AvoidanceGrant a request only if the resulting state remains safe; e.g., Banker’s algorithm.Before granting a request
Detection & recoveryAllow allocations, detect deadlock, then break it by aborting/rolling back a process or preempting a resource where possible.After deadlock occurs

Memory aid: Prevention = stop the conditions; Avoidance = check safety first; Detection & recovery = find and fix.

Classroom note: An unsafe state is not necessarily a deadlocked state. Avoidance checks whether a safe completion sequence remains possible.
